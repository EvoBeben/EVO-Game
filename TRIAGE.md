# TRIAGE — EvoBeben/EVO-Game — 2026-10-15

**Verdict: FIX** — a complete, well-tested single-season tool whose useful window has passed: everything is hardcoded to the 2026 draft, the data snapshots are frozen in July/August 2026, it is deployed nowhere, and 8 branches (3 holding unrelated unmerged apps) make the repo hard to pick back up for 2027 without a cleanup pass first.

**What it is:** "Draft Desk for Fantasy Football" — a 2026 fantasy draft guide/draft-room app (rankings, player lab with historical profiles, comparisons, injury/freshness labels, mock drafts for a two-flex lineup, persistent drafted/queue state) living in `fantasy-football-2026/`. Despite the repo name, there is no general "game" here — it is one fantasy-football tool plus branch-only experiments.

## Stack & structure

- Zero-dependency static site: one 3,801-line / 295 KB `fantasy-football-2026/index.html` (all CSS + JS inline, dark single-theme design) that `fetch()`es six auditable JSON files from `fantasy-football-2026/data/` at runtime (144 rankings, 634 Sleeper projections, 32 team reports, draft tips, who-to-watch, ESPN league history for 2024/2025) and embeds historical player profiles (NFLverse 2013–2025) as one giant inline JSON blob.
- Python data pipeline (stdlib): `build-data.py` generates/validates the embedded historical profiles from NFLverse; `refresh-merged-data.py` refreshes the Sleeper snapshot from the Sleeper API.
- `package.json` exists only to run tests: `npm test` → `node --test tests/*.test.mjs`. No build step, no framework, no bundler.
- Because data loads via `fetch()`, the page only works served over HTTP — opening `index.html` from `file://` fails silently-ish. Nothing in the repo says this (root README is 2 lines).

- Data freshness is the core rot: in-page provenance dates are rankings 2026-07-30, projections/injuries fetched 2026-08-13, team reports 2026-07-25. That was right for an August draft; mid-season it is stale, and "2026" is hardcoded in filenames, the localStorage key (`draft-desk-2026-state-v1`), Sleeper endpoints, and copy — a 2027 rerun is a rename-everything exercise, not a refresh.
- The 3,801-line monolith: the embedded player-data blob is a single multi-hundred-KB line inside the HTML, generated by `build-data.py` but pasted/committed inline — any data fix means regenerating and re-committing the whole file, and diffs are unreviewable.
- Tests are honest-label/feature-presence checks (regex over HTML), not behavioral tests of the draft logic itself; the Python pipeline has no tests.
- Agent-workflow docs (`CODEX-PROMPT.md`, `UPDATE-PROMPT.md`) are committed alongside the app — useful history, but they read as instructions to future agents rather than product documentation.

## The 5 improvements (ranked by impact/effort)

1. **Make the season a parameter, not a filename** — `2026` is hardcoded in data filenames, the localStorage state key, Sleeper endpoint URLs, and page copy; extract a single season config so the 2027 refresh is `refresh-merged-data.py` + `build-data.py` and a config bump, and archive the 2026 snapshot as-is if it is only a keepsake.
2. **Deploy it or declare it local-only** — there is no deploy config of any kind; the app is pure static, so GitHub Pages serving `fantasy-football-2026/` (or a `vercel.json`) is a minutes-long change that makes the next draft day a URL instead of a clone-and-serve ritual.
3. **Clean up the 8-branch sprawl and evict the unrelated apps** — `tech-pricing-stock-comparison` (+3) and `trending-items-ranking-app` (+1) are separate products squatting on branches of a football repo, and the Bears-news branch holds +5 unmerged commits 36 behind; split them to their own repos or close them, land or drop the Bears work, and delete the five branches that are identical to or fully behind `main` (`GROK`, `PIKA`, `agent/draft-day-readiness`, `claude/fantasy-football-breakdown-t9bnfk`, `claude/mock-drafts-2-flex-pwj17h`).
4. **Write a real README and fix the repo identity** — root README is "# EVO-Game / Evo Game" (2 lines) and the GitHub description says the same; document what Draft Desk is, that it must be served over HTTP (`fetch()` fails on `file://`), how to run tests, and how to refresh data — and set the repo description to match.
5. **Split the generated player-data blob out of `index.html` and add behavioral tests** — emit the historical profiles to a `data/history.json` the page fetches like the other six datasets (or a generated JS include) so `index.html` drops back to reviewable code, and add a small DOM-level test (e.g. drafting a player updates counts/queue) so the suite tests behavior, not just string presence.
